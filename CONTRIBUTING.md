# Contributing to EMF

## The ground rules

1. **Research and education only.** No advice, recommendations, price targets or performance claims.
2. **Public material only.** Never submit client data, personal holdings, confidential or proprietary
   information belonging to you or anyone else, or anything you are not free to license under MIT.
3. **Label what you know.** Mark each claim as established (with a source), a hypothesis, or untested.
   Say when an AI model drafted part of a contribution.
4. **Credit is part of the receipt.** When you adopt someone's idea, data or wording, name them and link
   the source, worded as authorship, before the content that uses it.

## Sign-off (Developer Certificate of Origin)

Every commit carries a `Signed-off-by:` line (`git commit -s`). It certifies, under the
[Developer Certificate of Origin 1.1](https://developercertificate.org/), that you wrote the change or
have the right to submit it under this project's license.

## Contributors

Add one file to `contributors/emails/` named after your commit email, containing your GitHub handle. One
file per person means these additions never conflict. (Pattern adapted from Nous Research's Hermes Agent,
[`contributors/emails/`](https://github.com/NousResearch/hermes-agent/tree/main/contributors/emails).)

## How changes land

Open a pull request. Each one is reviewed before it merges. A rule with a testable claim should ship with
the test, or say plainly that it is untested.
